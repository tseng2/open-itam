# IT Agent 升级为自研资产管理系统（ITAM）规划

本项目原定位于“终端数据采集 Agent + Snipe-IT 数据同步”，现因定位升级，将全面演进为**“自研 IT 资产管理系统（Server 端） + 自动化采集器（Agent 端）”**的完整解决方案。

本文档梳理了基于此目标的规格调整及全新功能演进路线。

## 🔴 原规划需移除或调整的设计（Deprecations）

1. **移除 Snipe-IT 强关联**
   - 移除 `architecture.md` 中的 Snipe-IT 连接器（Connector）设计。
   - 移除 `/api/v1/assets/sync-snipeit` 同步 API。
   - `FEATURES.md` 中的“Snipe-IT 数据导入/同步”阶段作废。
2. **数据源定位反转**
   - 原设计：IT Agent 服务端为中间件，Snipe-IT 为最终资产台账（Source of Truth）。
   - **新设计**：IT Agent 服务端本身即为**企业 IT 资产台账的唯一事实源（Source of Truth）**。
3. **数据库演进驱动力变更**
   - 原设计中切换 PG/MySQL 的原因是“与 Snipe-IT 深度集成”。
   - 新设计下，随着 CMDB（配置管理数据库）数据模型复杂度的提升（需处理资产、组织架构、人员、位置、维保等多维关系），**PostgreSQL/MySQL 将成为必选项**，建议在阶段一直接完成数据库底座的平滑迁移。

## 🟢 新增核心模块规划（Server 端能力扩展）

为取代 Snipe-IT，服务端需补充完整的 CMDB 与资产全生命周期管理能力：

### 1. 集团化多公司隔离 (Group Company Model)
*适应集团架构，将资产管理按所属公司切分。*
- **多公司资产池**：引入“所属公司（Company/Tenant）”维度（如：公司A、公司B），确保不同公司的硬件资产、软件 License 相互独立。
- **权限与数据可见性**：支持集团视角（全局可见）与分公司视角（仅可管理本公司资产），防止数据越权。

### 2. 资产全生命周期管理 (Asset Lifecycle Management)
*原架构仅支持 Agent 采集上报的“在线/离线”状态，现需扩充业务状态。*
- **状态流转**：入库 (In-stock) -> 领用/分配 (Deployed) -> 维修 (Maintenance) -> 报废 (Retired) -> 丢失 (Lost)。
- **资产录入**：支持非 Agent 设备（如显示器、打印机、网络设备、投影仪）的批量导入（Excel/CSV）与手动录入。
- **派发与归还**：支持将资产绑定至具体员工，并记录派发/归还时间。
- **生命周期追溯**：每个资产拥有独立的时间轴（Timeline），记录采集变更（如换内存）与业务变更（如张三流转给李四）。

### 3. 组织架构与人员映射 (Identity & Organization)
*资产必须归属到人或部门，以支撑财务与安全管理。*
- **AD 数据源深度集成**：复用 `ad-selfservice` 项目架构（支持双域及按部门路由）。直接通过 API 或数据库拉通员工人员名单及组织层级。
- **身份网关联动**：参考 `ad-selfservice` 中 Identity Hub + System Slot 架构，在本项目中也保持与 `ad-selfservice` 生命周期编排引擎的兼容性（后续亦可作为下游子系统接入离职/调岗通知 fan-out）。
- **自动绑定**：结合 Agent 采集的 `logon_domain\logon_user`，实现资产与使用人的**自动匹配与建议绑定**，减少 IT 人工维护成本。

### 4. 资产分类与扩展字段 (Taxonomy & Custom Fields)
- **用友 U8 采购订单号关联**：为硬件资产增加“U8采购订单号”字段，以便与公司的用友 U8 v18 财务/采购系统拉通，方便追溯供应商信息与采购明细。
- 支持资产分类树（如：IT设备 -> 笔记本 -> Windows笔记本）。
- 支持更多自定义字段（如：过保时间、资产标签号、折旧方式），并支持检索与导出。

### 5. 软件与授权管理 (Software & License Management)
- 基于 Agent 上报的软件列表，提取商业软件（如 Office、AutoCAD、Adobe 等）。
- 管理软件 License（总数、已分配数、到期日），并与 Agent 采集的数据比对，形成**合规性报表（识别盗版与超用）**。

### 6. 条码/二维码盘点（预留接口）
- 资产管理后台预留条码/二维码（QR Code）的字段与接口，未来可扩展手机端扫码查阅与盘点功能。

## 🚀 调整后的实施路线图 (Roadmap)

基于现有进度（P0-P4 基础采集和告警已成型），新的演进阶段调整如下：

### 阶段一：资产台账底座重构（当前首要任务）
- [ ] **数据库重构**：引入 PostgreSQL/MySQL 作为主库（通过 GORM 等 ORM 或扩展当前 Store 接口），建立完整 CMDB 关系模型（资产表、用户表、部门表、分类表）。
- [ ] **多公司组织架构底座**：引入集团/多公司划分逻辑，所有核心表（资产、用户）必须挂载 `company_id` 或 `domain` 标识，为后续分公司权限控制打底。
- [ ] **业务状态机**：为设备增加业务状态字段（库存、使用中、维修、报废等）。
- [ ] **UI 资产大盘升级**：提供类似 Snipe-IT 的资产列表、详情页、时间轴展示，并支持按“公司”切分视图；支持手动添加带有“U8采购单号”的外设资产。

### 阶段二：自动化与用户认领（实现真正的 IT 提效）
- [ ] **人员目录同步**：参考 `ad-selfservice` 的架构，接入双域 AD 同步员工与组织架构目录，区分人员所属的集团子公司。
- [ ] **人机自动绑定**：通过 Agent 报送的 logon_user 自动提示 IT 人员确认绑定。

### 阶段三：软件合规与深度采集（Mac 与 进阶）
- [ ] **macOS 全量支持**：补齐 macOS Agent 采集与部署（原 P5）。
- [ ] **软件 License 管理**：在后台建立受控软件库，与 Agent 采集的软件进行比对审计。
- [ ] **自动更新与推送**：实现 Agent 的自动更新和基础远程脚本执行（原 P6/P7）。

### 阶段四：安全协同与系统互联
- [ ] **子系统生命周期联动**：对齐 `ad-selfservice` 的 System Slot 架构（与云链CRM的 fan-out 机制类似），接收离职、调岗等生命周期事件进行资产收回或转移提醒。
- [ ] **USB 管控与审计**：落实移动介质插拔审计与策略管控（原 P9）。
- [ ] **端点合规判定**：提供合规状态 API，供内网安全设备（如 NAC/深信服）拉取进行网络准入联动。
- [ ] **移动端扫码预留**：开放二维码/条码盘点扩展接口。
